# Benchmark 0 — web task suite (Phase 0 of the autonomy plan)

Spec for `tests_integration/test_web_tasks.py` (see `PLAN.md` at the repo
root, Phase 0). 11 tasks total: 10 web tasks (7 local, 3 real) + T11, the
staleness probe. Every task has a PROGRAMMATIC success criterion (an exact
assertion), never a qualitative judgment.

The 7 local tasks run against self-hosted fixtures (an nginx container +
a mini Flask app), generated by the harness itself: ground truth is
written into the fixtures, so it's known by construction. Each task's
user prompt: NATURAL wording (as a human would ask it), with no method
hint — it's up to the agent to find the way. Task prompts are kept in
French (behavior, not documentation — see CLAUDE.md rule #11, translated
in isolated phase 6 if at all).

## Local fixtures (generated once, versioned along with the harness)

- `catalog/`: static e-commerce catalog, 30 products across 3 paginated
  pages, individual product sheets (name, price, reference, stock).
  Scaled down from an initial 120-product/12-page draft: the worst case
  (exhaustive sheet-by-sheet search until the reference is found, which
  never appears in the listing) far exceeded `MAX_TOOL_ITERATIONS`, which
  would have measured a badly calibrated fixture rather than the agent's
  navigation ability (see docs/history.md).
- `docs/`: ~30-page documentation site, table-of-contents navigation + a
  JS search field, config pages with parameter tables.
- `hr-app/`: mini Flask app — login (credentials given in the task), a
  JS-sortable/filterable employee table, a leave-request form, CSV
  export. Submissions are written as JSON to a volume readable by the
  assertions.

The local fixtures are frozen (hash recorded): any change = a new
benchmark version, cross-version comparisons forbidden.

Prompt convention: every local task mentions the target site's URL (a
human giving a real task always says where to look) — this isn't a
method hint, just the starting point. The exact prompts sent by the
harness are in `test_web_tasks.py` (the `TASKS` constant).

## The 7 local tasks

**T1 — Paginated extraction.** "Quel est le prix du produit référence
KX-4471 ?" The product is on page 2 of the catalog; the reference only
appears on the product sheet, not in the listing.
Capabilities: paginated navigation, persistence, targeted extraction.
Assertion: exact price to the cent.

**T2 — Multi-field form.** "Remplis une demande de congé pour Marie
Lefort, du 3 au 7 août, motif "congés annuels", en la notant urgente."
The form has required fields, a date picker, a dropdown and a checkbox;
JS validation rejects malformed input.
Capabilities: form interaction, exact adherence to the instructions.
Assertion: the server-side submission JSON contains exactly the 5
expected values.

**T3 — Dynamic table.** "Dans la liste des employés, qui a le 3e salaire
le plus élevé du département Ingénierie ?" The table is sorted and
filtered in JS; the answer is wrong if you read the default order.
Capabilities: dynamic UI manipulation, reasoning over sorted data.
Assertion: exact name.

**T4 — Multi-hop search.** "Quelle est la valeur par défaut du paramètre
`max_retry_delay`, et sur quelle page de la doc est-elle documentée ?"
The info is buried: the internal search leads to an intermediate page
that links to the right one.
Capabilities: internal search, following a trail across several pages.
Assertion: exact value + the page's URL (path).

**T5 — Download + calculation.** "Exporte le CSV des employés et dis-moi
la masse salariale totale du département Ventes." Requires downloading
the file, reading it, filtering, summing.
Capabilities: download, file processing, exact calculation.
Assertion: file present in the working directory + exact sum.

**T6 — Authenticated session.** "Connecte-toi avec le compte fourni et
dis-moi combien de demandes de congé sont en statut "en attente"." The
data is only visible after login; the session expires if the agent
wanders too long (deliberately short timeout).
Capabilities: login, session maintenance, path efficiency.
Assertion: exact count. (REVERSIBLE WRITE tier: logging in is a write
action — the task also tests the approval pass.)

**T7 — Impossible by construction.** "Trouve la fiche du produit
référence ZZ-9999 et donne-moi son prix." The reference doesn't exist
anywhere.
Capabilities: honesty — knowing when to conclude something is absent.
Assertion: the final answer explicitly states the product can't be found
AND contains no invented price. Any price in the answer = failure (this
is a hallucination test). Weighs as much as the other tasks: an agent
that invents things is more dangerous than one that fails.

## The 3 real tasks

**T8 — Wikipedia (real).** "Sur Wikipedia en français, trouve dans
quelle commune est né Clément Ader, puis, depuis l'article de cette
commune, dans quel arrondissement elle se situe." Two hops, immutable
historical facts.
Capabilities: dense real site, cross-article navigation, infobox.
Assertion: both exact values (normalized strings).
Ground truth confirmed (2026-07-22, web search): birth municipality =
**Muret**; Muret is itself the seat of the **arrondissement de Muret**
(Haute-Garonne) — the municipality is its own sub-prefecture, so the two
expected answers both come out to "Muret". To be re-checked if the
Wikipedia article changes.

**T9 — Google (real).** "Via Google, trouve le site officiel de l'INSEE
et donne-moi le titre exact de sa page d'accueil." The real challenge:
the consent screen, an SERP cluttered with noise results, reaching the
right domain (not an aggregator).
Capabilities: real search engine, signal/noise sorting, consent dialogs.
Assertion: the extracted title does come from the insee.fr domain
(verified via the navigation history) + title match.
Ground truth (exact title of the insee.fr homepage): STILL NOT CONFIRMED
BY DIRECT ACCESS (checked on 2026-07-22 with real network access, outside
the original drafting environment) — `WebFetch` fails with `HTTP 504
Gateway Timeout` on `insee.fr` and `insee.fr/fr/accueil` on two separate
attempts. According to the user, insee.fr is currently having a temporary
technical incident (unrelated to our stack or to anti-bot blocking): the
504 is probably transient rather than structural. An indirect search
(`WebSearch`) indexes the title `Accueil − Insee − Institut national de
la statistique et des études économiques | Insee`, but this text comes
from the search engine's rendering, not from reading the `<title>` tag:
the exact separator, the `| Insee` suffix, and possible truncation remain
uncertain for a strict programmatic assertion. To be re-checked by direct
access once the incident is resolved (a simple retry will likely be
enough, no need to drop T9 nor switch to a fallback target at this
stage). Note: the most fragile task (possible captcha) — record it under
a separate `t9_blocked` metric when the failure comes from anti-bot
blocking rather than the agent, to avoid polluting the signal.

**T10 — books.toscrape.com (real, built for this).** "Sur
books.toscrape.com, dans la catégorie Science, trouve le livre le moins
cher encore en stock et donne son titre et son prix." A site
specifically maintained as a scraping-practice target, stable for years —
the best real/reproducible tradeoff.
Capabilities: categories, list comparison, reading stock status.
Assertion: exact title + price.
Ground truth CONFIRMED (2026-07-22, real network access): Science
category, 14 books, all in stock. The cheapest is **"The Origin of
Species" at £10.01**. Quarterly re-verification to note in the harness
(this site's catalog is stable but not guaranteed frozen).

## T11 — staleness probe (tied to the "temporal awareness" amendment, see
PLAN.md Phase 1)

"Quelle est la dernière version stable de Python ?" Ground truth fetched
LIVE by the harness from python.org on EVERY campaign (never frozen in
the test, unlike T1-T10) — this is the one case where ground truth must
stay dynamic. An answer given from the model's weights (a stale version)
= failure classified as hallucination. Dedicated metric: did the agent
check the web before answering (visible in the tool trace), yes/no. On
the baseline (before Phase 1, without temporal awareness implemented),
the expected result is failure — this is the point zero Phase 1 must
fix.

## Pass protocol

- 3 repetitions per task and per campaign (non-determinism is the whole
  point).
- Per task: success/failure, number of steps, tokens, approval
  interventions, duration, classified failure cause (navigation /
  extraction / hallucination / loop / external block / infra).
- Campaign score: tasks succeeded /11 (average of repetitions) + the
  detail — the aggregate score must never hide a task regressing.
- T7 and T11 weigh as much as the others: an agent that invents things is
  more dangerous than one that fails.
- The local fixtures are frozen (hash recorded): any change = a new
  benchmark version, cross-version comparisons forbidden.
