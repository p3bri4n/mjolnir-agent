# Tests and streaming

Content moved as-is from README.md (restructuring effort, see docs/briefs/restructuration-et-anglais.md, phase 3) — no rewrite at this stage.

`.github/workflows/ci.yml` runs each service's `tests/` suite (never
`tests_integration/`, which needs a live stack) on every push to
`main`/`dev` and every pull request, one matrix job per service, with the
same install commands as below.

Each service has its own pytest suite, isolated from the others (no shared
dependency between services, just like in production where each one runs
in its own Docker image). To run a service's suite:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-test.txt -r services/<service-name>/requirements.txt
cd services/<service-name> && python3 -m pytest tests/ -v
```

Use `python3 -m pytest`, not the bare `pytest` command: each service
imports its application code as `import app.main`, which assumes the
service's directory (`services/<name>`) is on `sys.path`. `python3 -m`
adds it automatically; the `pytest` executable alone doesn't always do
so, depending on the test discovery mode, and then fails with
`ModuleNotFoundError: No module named 'app'`.

No real third-party service is needed to run the tests: Qdrant runs in
`:memory:` mode, the MCP servers are replaced by real small test servers
(same protocol and stdio transport as in production, but without Docker),
and HTTP calls to the other microservices as well as to the LLM are
intercepted by [`respx`](https://github.com/lundberg/respx) (which
patches the HTTP transport, not the `httpx.AsyncClient` class itself —
see below for why this distinction matters).

For `context-manager`, the test suite doesn't need `sentence-transformers`
or `torch` (heavy dependency): `EMBEDDING_MODEL=fake` (already set in
`tests/conftest.py`) switches to a deterministic embedder with no network
dependency. This variable must never be used in production. The generic
command above still installs `sentence-transformers` since it's part of
`requirements.txt`; to skip it explicitly:

```bash
grep -v sentence-transformers services/context-manager/requirements.txt > /tmp/cm-reqs.txt
pip install -r requirements-test.txt -r /tmp/cm-reqs.txt
cd services/context-manager && python3 -m pytest tests/ -v
```

## Token-by-token SSE streaming

Implemented and covered by tests (`stream: true` on `/v1/chat/completions`):

- `call_llm` uses `llm.astream()` and merges the `AIMessageChunk` objects
  (`+=` operator) — including `tool_call_chunks`, which also arrive
  streamed in pieces and automatically merge into complete `tool_calls`.
- The HTTP endpoint uses `agent_graph.astream_events(..., version="v2")`
  and only forwards `on_chat_model_stream` events to the client — in
  practice, an iteration that triggers a tool call produces empty content
  on the LLM side (the tool_call travels over a separate channel), so the
  user never sees the agent "thinking" about which tool to use: only the
  final answer is displayed, token by token.
- SSE format compliant with the OpenAI API (`chat.completion.chunk`,
  `delta.content`, `finish_reason`, `data: [DONE]`).
- Non-streamed mode (`stream: false`) keeps working identically.

**Point of attention**: the combination `langgraph==0.2.34` +
`langchain-openai==0.2.2` + `openai==1.51.2` is the one that was tested
and validated for streaming. Upgrading any of these three dependencies
without re-validating `ChatOpenAI.astream()` under real conditions risks
reintroducing the regression described above.
